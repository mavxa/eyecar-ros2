# eyecar_teleop

Первый ROS 2 пакет АЙКАР. `keyboard_teleop` публикует
`geometry_msgs/msg/Twist` в `/cmd_vel`:

- `W` — вперёд;
- `S` — назад;
- `A` — поворот влево;
- `D` — поворот вправо;
- `Space` — остановка;
- `Q` — остановка и выход.

Оси управляются независимо, поэтому работают сочетания `W+A`, `W+D`, `S+A`
и `S+D`. В Kitty и других терминалах с Kitty keyboard protocol нода получает
события отпускания клавиш: газ или руль сбрасываются сразу. В остальных
терминалах используется автоповтор с аварийной остановкой при пропаже ввода.
`Space` сразу сбрасывает газ и руль.

Поддерживаются английская и русская раскладки клавиатуры: физические клавиши
`WASD/Q` распознаются также как `ЦФЫВ/Й`.

`keyboard_teleop` является только publisher: USB-драйвер Arduino Mega постоянно
работает отдельным user-сервисом `eyecar-base.service`. При нажатии и
отпускании команда отправляется немедленно; пока клавиша удерживается, она
повторяется с частотой 20 Гц. Через 0.5 с без событий срабатывает остановка.
Значения по умолчанию: `W=0.18`, `S=-0.25`, поворот `0.85`.

На Pi из интерактивного SSH-сеанса:

```bash
ros2 run eyecar_teleop keyboard_teleop
```

В строке запуска должно быть `key releases=True`, если терминал поддерживает
протокол. Если `False`, нода работает через автоповтор клавиш.

Параметры:

```bash
ros2 run eyecar_teleop keyboard_teleop --ros-args \
  -p forward_speed:=0.18 \
  -p reverse_speed:=0.25 \
  -p angular_speed:=0.85 \
  -p command_timeout:=0.5 \
  -p publish_rate:=20.0
```

## Steam Deck через SSH

Существующая `keyboard_teleop` поддерживает два режима: в интерактивном
терминале — клавиши, с перенаправленным stdin — аналоговые стики через SSH.
ROS-имя ноды и команда запуска остаются `keyboard_teleop`.
Левый стик по умолчанию управляет газом (ось Y) и рулём (ось X): отклонение
стика задаёт величину команды пропорционально, с мёртвой зоной 0.12.

Нода работает на Pi. На Steam Deck нужен Python 3 и контроллер,
доступный как `/dev/input/js*`; ROS на Deck не нужен. Это тестовый вариант:
для проверки укажите `topic:=/cmd_vel_test`, реальные моторы его не получают.
Обычный выход `keyboard_teleop` остаётся `/cmd_vel`.
Ввод читает `scripts/steamdeck_input.py` из корня репозитория. Скопируйте его
на Deck. В Desktop Mode проверьте, что Steam Input предоставляет gamepad,
а не только эмуляцию клавиатуры/мыши. Если `/dev/input/js*` отсутствует,
этот скрипт с текущим режимом ввода работать не будет.

Сначала определите номера осей и кнопок на Deck:

```bash
python3 steamdeck_input.py --device /dev/input/js0 --inspect
```

Начальные настройки: ось 1 — газ, ось 0 — руль, кнопка 4 — разрешение
движения, кнопка 1 — стоп. Это настраиваемые индексы, а не проверенная
распиновка Steam Deck. Номера, показанные `--inspect`, нужно сверить и при
необходимости передать через `--throttle-axis`, `--steering-axis`,
`--enable-button`, `--stop-button`. Знаки обеих осей по умолчанию `-1`:
отклонение вверх даёт положительный газ, вправо — отрицательный angular.z.
Для другой ориентации есть `--throttle-sign 1` и `--steering-sign 1`.

На Deck (SSH-профиль `eyecar` должен быть настроен отдельно на самом Deck):

```bash
python3 steamdeck_input.py | ssh -T eyecar \
  'source /opt/eyecar-vision/ros-env.bash; exec ros2 run eyecar_teleop keyboard_teleop --ros-args -p topic:=/cmd_vel_test'
```

Можно заменить `eyecar` на `griftf@eyecar.local`, если у griftf есть SSH-доступ.
Не используйте `ssh -t`: нода принимает JSON-строки через стандартный ввод.
На Pi в другом терминале смотрите тестовые команды:

```bash
source /opt/eyecar-vision/ros-env.bash
ros2 run eyecar_teleop cmd_vel_monitor --ros-args -r /cmd_vel:=/cmd_vel_test
```

Для начала движения отпустите кнопку разрешения и верните стики в центр,
затем удерживайте кнопку разрешения. Отпускание кнопки, кнопка стоп, ошибка
ввода или отсутствие пакетов 0.4 с обнуляют команду. После таймаута или стопа
нужно снова отпустить кнопку и центрировать стики. Пакеты отправляются 20 Гц,
мёртвая зона — 0.12; скорости как у клавиатуры: вперёд 0.18, назад 0.25,
поворот 0.85. EOF/закрытие SSH завершает ноду с нулевой командой; драйвер и
Arduino также сохраняют свои таймауты остановки.

После проверки кнопок и направлений, с вывешенными колёсами, можно переключить
выход на `/cmd_vel`. Остановите другие программы, публикующие движение,
включая другие экземпляры `keyboard_teleop` и `modul1.py`, чтобы команды
не чередовались:

```bash
python3 steamdeck_input.py | ssh -T eyecar \
  'source /opt/eyecar-vision/ros-env.bash; exec ros2 run eyecar_teleop keyboard_teleop'
```

Настройки ROS-ноды: `topic`, `forward_speed`, `reverse_speed`,
`angular_speed`, `command_timeout`, `deadzone`, `publish_rate`.

Аналоговый режим останавливается при потере пакетов через 0.4 с.
Клавиатурный режим принимает WASD и стрелки (CSI/SS3); в обычном терминале
таймаут 0.5 с применяется отдельно к газу и рулю. Удержание руля не сохраняет
газ после прекращения повторов W/S, и наоборот. Для сочетаний в Steam Input
без событий отпускания повторяйте каждое назначенное направление 50–100 мс.
Само SSH-соединение не передаёт события джойстика: передатчик на Deck обязателен
для пропорционального управления стиками.
